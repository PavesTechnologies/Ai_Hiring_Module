# ==============================================================================
# CI-only dependency set - referenced by Jenkinsfile.ci (requirementsPath).
#
# buildPythonCIPipeline runs a bare `pip install -r <requirementsPath>` with no
# index or platform flags, so anything the install needs has to be expressed
# in this file. Two things do:
#
#  1. torch. On the arm64 build agent, `torch==2.13.0` resolves from PyPI to
#     2.13.0+cu130 - the Grace/sbsa CUDA build - dragging in the whole nvidia-*
#     CUDA runtime and triton, several GB, on every pull request. The
#     --extra-index-url below plus the explicit +cpu pin gets the CPU wheel
#     instead. This is the same thing arm.Dockerfile does at image build time;
#     both routes must agree or CI tests something the image never ships.
#
#  2. psycopg2. requirements.txt pins BOTH psycopg2 (source, needs pg_config
#     and gcc on the agent) and psycopg2-binary. Inheriting from
#     requirements.prod.txt rather than requirements.txt drops the source one -
#     see the removal notes in that file.
#
# The +cpu pin and the plain `torch==2.13.0` inherited below are compatible:
# PEP 440 says the specifier `==2.13.0` matches the local version `2.13.0+cpu`.
# ==============================================================================

--extra-index-url https://download.pytorch.org/whl/cpu

torch==2.13.0+cpu

# The runtime dependency set the image itself installs.
-r requirements.prod.txt
